# BackLog v0.5 Quality Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship BackLog v0.5.0 as a safer, easier, one-download Windows application for non-technical users on an 8 GB laptop.

**Architecture:** Preserve the current Tauri, TypeScript, Rust, and Python architecture while tightening its lifecycle boundaries. Saved configuration records user intent, runtime helpers derive safe effective behavior, the pipeline explicitly reconciles interrupted work, and the frontend exposes one-step setup and recoverable downloads. A guarded Windows GitHub Actions workflow produces the installer without weakening the existing signed updater channel.

**Tech Stack:** Tauri 2, Rust, TypeScript, Vite, Python 3.11, Playwright, GitHub Actions, NSIS

## Global Constraints

- Release version is `0.5.0`.
- Windows x64 is the supported downloadable release platform.
- The primary Qwen3 0.6B Q8 GGUF is bundled and verified by SHA-256.
- The Qwen3 1.7B Q8 escalation GGUF remains optional.
- Recommended settings must remain safe on a Windows laptop with 8 GB RAM and no dedicated GPU.
- No document content, names, or secrets may be sent to external services during processing.
- Stable updater publication requires a valid Tauri updater signature.
- Existing v0.4.4 updater metadata must remain untouched if the signing key is unavailable.
- User-facing copy must avoid developer terminology when a plain-language alternative exists.

    Ok(conn.execute(

- [ ] **Step 3: Write a failing shutdown-latch test**

- [ ] **Step 4: Implement the shutdown latch**

Add `shutting_down: AtomicBool`. Check it before and after acquiring a model
slot in `ensure_up`. `begin_shutdown()` sets it with `Ordering::SeqCst` and
then takes both server slots. `shutdown()` remains the server-kill primitive;
normal tests and drop paths call `begin_shutdown()`.

Run: `cargo test -p backlog --lib slm::tests --locked`

Expected: PASS.

- [ ] **Step 5: Wire orderly shutdown and startup recovery**

In `stop_pipeline_inner`, pause and close intake, call
`pipeline.slm.begin_shutdown()`, then call
`pipeline.ledger.release_all_claims()`. Log the released count without leaking
document identifiers. Remove the sleep-and-second-kill workaround.

On startup, release claims left by an earlier process before the watcher starts.
This makes restart recovery immediate instead of waiting up to 72 minutes.

- [ ] **Step 6: Make persisted terminal evidence authoritative**

Before model work, if an existing manifest for the job is valid and matches the
content hash, reconcile the ledger to the corresponding terminal state rather
than rerunning the model. If a quarantine or manifest write fails during
flagging, release the claim and leave the job non-terminal so it can retry.

Add tests using a temporary outbox and ledger for:

- valid ok manifest advances to emitted without model execution;
- failed flagged-manifest persistence leaves the job claimable;
- malformed or hash-mismatched manifest is ignored.

Run: `cargo test -p backlog --lib pipeline::tests --locked`

Expected: PASS.
