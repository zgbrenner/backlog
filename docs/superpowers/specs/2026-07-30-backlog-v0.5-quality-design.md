# BackLog v0.5 Quality Release Design

Date: 2026-07-30
Status: Approved for implementation

## Context

BackLog v0.4.4 is a mature Windows desktop application with a working offline
primary-model installer. The next release should preserve that simple deployment
while fixing the highest-risk reliability and usability seams found in the
pipeline, model setup, first-run experience, and release process.

The user asked for best-judgment execution without a design review round trip.
This design is therefore self-approved after independent pipeline, UX, and
release audits.

## Goals

- Keep every accepted document recoverable across shutdowns, crashes, and retries.
- Make the primary-model fallback honest and deterministic.
- Make first-run setup understandable without technical knowledge.
- Keep defaults safe on an 8 GB Windows laptop without a dedicated GPU.
- Preserve a single downloadable installer that works offline after download.
- Make CI and releases reproducible from a clean public GitHub repository.
- Avoid breaking the existing signed updater channel when signing credentials are
  unavailable.

## Non-goals

- Replacing the current ledger with a new delivery/content identity system.
- Bundling both the primary and optional escalation model in one installer.
- Authenticode signing without a trusted Windows code-signing certificate.
- Adding document-page previews.
- Redesigning the application around bulk approval actions.

## Approaches Considered

### A. Cosmetic and feature-only release

Improve labels, setup instructions, filters, and empty states while leaving the
pipeline and model behavior unchanged.

Rejected because it would make the product look more polished without resolving
crash recovery and model-download correctness.

### B. Targeted stabilization release

Add bounded recovery and shutdown behavior, separate configured model intent from
the effective runtime fallback, improve first-run and download controls, reconcile
documentation with the real installer, and automate a guarded Windows release.

Selected because it delivers the greatest reliability and usability improvement
without destabilizing the mature core.

### C. Full ledger and delivery-identity rewrite

Separate physical deliveries from content hashes, introduce transactional
manifest state, and redesign all duplicate, replay, and resubmission behavior.

Deferred because it is a larger migration with compatibility and recovery risks
that cannot be justified for this release.

## Design

### 1. Durable pipeline recovery

Claims will be explicitly released during controlled shutdown and stale claims
will be recoverable on startup. The model server will gain a shutdown latch so a
background request cannot respawn it while the app is exiting.

Before rerunning model work, processing will recognize an existing valid manifest
as authoritative recovery evidence and advance the ledger accordingly. Flagging
will not leave an untracked terminal row if quarantine or manifest persistence
fails. Failures will remain retryable and visible.

The full duplicate-delivery identity rewrite is deferred. This release will make
the existing behavior explicit and prevent silent loss where a safe bounded
recovery is possible.

### 2. Honest model configuration and fallback

Saved configuration will continue to express the user's desired primary and
escalation models. Normalization will no longer rewrite a missing escalation path
to the primary path.

Runtime selection will compute an effective model path:

1. Use the configured escalation model when it is installed and valid.
2. Otherwise reuse the valid primary model for escalation work.
3. Report that state as a functional, degraded fallback rather than pretending
   both models are installed.

Downloads will always target distinct canonical destinations. Completion will
update saved configuration before readiness is refreshed. Cancelled downloads
will remain resumable.

### 3. Resource-safe defaults

Backend normalization will own concurrency limits so UI presets and imported
configuration cannot overcommit a low-memory machine. The recommended 8 GB
profile will use conservative conversion and model concurrency.

Preflight will distinguish blocking failures from degraded but usable states.
The UI will summarize those states in plain language and keep technical details
available without making them the primary instruction.

### 4. First-run and daily usability

An unconfigured app will lead with a compact three-step setup:

1. Choose the Processing, Done, and Power Automate folders.
2. Save the folders and check this computer in one action.
3. Download the primary model if it is missing.

The model download surface will support cancel, resume, and terminal-state
recovery after navigation or restart. The main view will distinguish a caught-up
processing queue from outstanding reviews and clarify that Done means handed to
Power Automate, not confirmed in SharePoint.

Pending approval undo state will not be silently committed by ordinary in-app
navigation. Review controls will gain compact filtering and ordering without
unsafe bulk approval.

### 5. One-download Windows release

The installer will include:

- the BackLog desktop application;
- the conversion sidecar and its Python runtime;
- the llama server and required runtime libraries;
- the verified Qwen3 0.6B primary model;
- the offline WebView2 bootstrapper.

The optional 1.7B escalation model will remain an in-app download. This keeps the
installer practical while ensuring the application is useful offline immediately
after installation.

Public GitHub Actions will perform the Windows build and release from a clean
checkout. Public-repository Actions have no billable-minute cost for the owner.
The workflow will verify model and binary hashes and fail closed on missing
inputs.

If the existing Tauri updater private key is available as a repository secret,
the workflow will publish a stable release with the installer, signature, and
`latest.json`. If it is not available, the workflow will publish an unsigned
prerelease installer and leave the v0.4.4 stable updater metadata untouched.
This avoids delivering an update that existing installations cannot verify.

### 6. CI and documentation

CI will stage a small deterministic model fixture so Tauri resource validation
does not fail on an empty model directory. Local CI instructions will match the
real workflow.

README, user guide, and release documentation will describe the actual package:
the primary model is bundled and the escalation model is optional. Technical
release inputs will be pinned or verified by hash wherever practical.

## Error handling

- Interrupted downloads remain partial and resumable.
- Cancel is a normal terminal download state, not a generic failure.
- A failed quarantine or manifest write remains retryable and visible.
- Shutdown prevents new model-server starts before releasing claims.
- Release creation fails rather than publishing incomplete stable updater assets.
- Existing stable updater metadata is never replaced by an unsigned build.

## Testing strategy

- Rust unit tests cover configuration normalization, fallback selection, claim
  release, manifest recovery, shutdown latching, and RAM clamps.
- TypeScript harness scenarios cover unsaved first-run folders, save-and-check,
  download cancel/resume/failure, caught-up states, undo across navigation, and
  review filtering.
- Existing Python tests cover manifest and sidecar behavior.
- `npm run check`, harness assertions, and repository validation run locally.
- GitHub Actions performs the authoritative Windows Rust, packaging, and installer
  verification because the local environment does not provide the Rust toolchain
  or Windows packaging runtime.

## Release acceptance

- All local checks pass.
- All required GitHub checks pass on the release commit.
- The release page contains a Windows installer with an immutable version.
- The installer contains the verified primary model and required sidecars.
- The download instructions require no separate runtime, model, or installer.
- Stable updater publication occurs only when its signature verifies.
